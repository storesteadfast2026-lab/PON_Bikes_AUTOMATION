# 06 — Product Check

Product Check compares received product codes with the active Product Master and identifies existing and NEW products.

## Step 2 access

When available, **Download Product Check + barcodes (.xlsx)** is shown directly in Step 2. Product Check remains downloadable before NEW product dimensions are entered.

**New Product Import** is also represented directly in Step 2: when ready it is a Download action; otherwise Step 2 shows why it is still pending or not required. No Generate/Regenerate action is exposed.

## Printed measurement units

The printable Product Check uses:

- `Length (cm)`
- `Width (cm)`
- `Height (cm)`

This is presentation-only. Confirmed ProductDefinition dimensions remain stored internally in millimetres. Example: 2000 mm is printed as 200 cm. Translogic-related internal/export logic continues to use the established mm representation.

## File provenance

Step 2 distinguishes file provenance for PON outputs. Product Check and New Product Import show **Generated** when a stored PON-generated copy exists, and **Uploaded** is shown separately as not applicable because these outputs are generated by PON rather than uploaded into it.

## PBP → PON historical classification (0930.1602)

For PON containers Product Check now applies a three-way exact classification using `code`, `pon_sku` and `code2`:

1. matching PON record → **Existing**;
2. no PON record but matching PBP record → **PBP → PON**;
3. no PON or PBP record → **New**.

`PBP → PON` is not counted as New. When the historical Product Master contains valid `cubic`, `weight`, `height`, `width` and `length`/`lenght`, those Translogic values are reused without asking the operator to re-enter dimensions. Product Check displays the migration status explicitly. If the active catalogue rows were imported before these optional fields were preserved in `raw_data`, PON can read the already-stored physical Product Master in memory to recover them; no database rewrite is performed.
