# 07 — NEW Product Process

Products not matched exactly to the active Product Master are treated as NEW for the current workflow.

The existing Product Check page collects the required Translogic product data. Dimensions are entered by the operator in centimetres and converted/stored internally in millimetres. Weight remains in kilograms.

Short Name is constrained by the existing Translogic naming rules; Long Name is retained separately. Group1 is resolved through the configurable Group1 family mapping. Group2 follows the existing cubic rule.

New Product Import becomes downloadable only when the current backend rules say it is ready. The Step 2 workspace does not bypass those rules.

## Optional direct Translogic replacement of numbered import files

Release 0929.1322 adds a guarded transfer step without changing New Product Import generation or file content.

The installer first inspects the **currently configured Translogic import destination folder** on the Windows host. It does not assume a filename. A usable numbered set must contain exactly one coherent pattern where five existing files share the same prefix and extension and differ only by the final number 1–5, for example conceptually `Prefix1.ext` through `Prefix5.ext`.

When exactly one real set is found and Docker has verified read/write access to that real folder, PON:

1. reads the actual names and extensions of files 1–5;
2. reads the actual last-write date/time of each file;
3. proposes the oldest file as the replacement target;
4. compares the real target extension with the extension of the PON-generated New Product Import;
5. shows the operator the generated source, detected real pattern, proposed target and target timestamp;
6. waits for explicit confirmation;
7. re-checks that the proposed target has not changed since the confirmation page was opened;
8. copies the generated bytes without conversion;
9. verifies the copied file by SHA-256;
10. records a transfer audit entry with timestamp, destination and replaced filename.

PON does **not** replace a numbered file automatically. If there is no unique complete 1–5 set, the real folder is unavailable, Docker cannot write it, or the generated extension differs from the real numbered-file extension, direct replacement remains disabled and the existing Download workflow stays available.

## PBP → PON migration rows (0930.1602)

New Product Import continues to use the existing generator and now also includes products classified **PBP → PON**. These rows are not New Products; they are historical PBP products that must be created under customer PON in Translogic.

For a valid historical PBP row PON reuses the historical `CODE`, `PON_SKU` identity/long-SKU value, `CODE2` matching identity, Short Name, Long Name, Cubic, Weight, Height, Width and Length. The PBP Group1 is never copied. Group1 is resolved again through the current PON family mapping. Group2 follows the existing cubic rule, including `CHG02` when Cubic is greater than 0.4.

The generated PON row uses Customer `PON`, Status `L`, Quantity `1`, Pallet `0`, Lift `1` and Outer `1`. If the historical physical measurements are incomplete/invalid, Product Check falls back to the existing manual ProductDefinition form for the missing operational data while keeping the classification **PBP → PON**.
